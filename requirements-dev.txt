# Obscura is driven over CDP, so its adapter needs a Playwright client even
# though the browser itself is not a Playwright one. Camoufox pulls Playwright
# in already; this makes the dependency explicit for anyone running only Obscura.
#
# Pinned, and the pin is load-bearing rather than tidiness. Playwright ships the
# Chromium build that `chromium` - the control - runs on, so an unpinned upgrade
# silently changes the baseline every other column is measured against, and does
# it without touching a line of our code or failing a test. Every control row in
# data/runs/ was taken on the build 1.60.0 downloads.
#
# It has already nearly happened: cloakbrowser's own requirement is a floating
# playwright and resolves to 1.62.0. It runs on 1.60.0 unchanged - checked
# 2026-08-13, same user agent, same markers - so the pin costs nothing and buys
# a control that stays comparable. Moving it is a decision to re-baseline, not
# a dependency bump.
#
# **It has now happened, and "nearly" is the word that has to come out.** The
# workstation venv holds playwright 1.62.0 against this 1.60.0, measured
# 2026-09-05 by `pip list` beside this file. Same failure as the patchright
# block below and for the same reason: a pin states what a fresh `pip install
# -r` would fetch, and nothing re-reads it afterwards, so this file kept saying
# 1.60.0 while the interpreter had moved.
#
# The sentence above - "Every control row in data/runs/ was taken on the build
# 1.60.0 downloads" - is therefore false, and the useful part is by how much.
# Read out of `engine_version` across every run file the same day, chromium rows
# only: **1607 on `148.0.7778.96 / playwright 1.60.0` against 17 on 1.62.0**,
# the 17 split `151.0.7922.34` x14 and `149.0.7827.201` x3. All 17 are in
# `b2b_recon_20260901T094129Z`, `engine_fingerprint_20260902T135127Z`, the three
# `tls_clienthello_20260902*` files and `tls_echo_20260902T180455Z`.
#
# **No `probehold_*` row is among them**, so the pass-rate baseline the control
# exists for is intact and nothing already measured needs retracting. What is
# broken is forward-looking and silent: the next chromium probehold run from
# this workstation would be taken on 151 and pooled with 1607 rows from 148
# without anything saying so. Three major Chromium versions apart, and the only
# thing that would record it is the `engine_version` field nobody reads until
# two numbers disagree.
#
# Not resolved here, because the two ways out are not equivalent and the choice
# is not a maintenance one: pin the venv back to 1.60.0 and keep the baseline,
# or accept 1.62.0, move this pin deliberately, and treat the 1607 rows as a
# closed series the way the patchright note below already does for its 43 files.
#
# **Resolved 2026-09-10, the user's call: the venv went back to 1.60.0 and the
# baseline stays.** `pip list` beside this file agrees with this line again, and
# `chromium.launch().version` answers `148.0.7778.96`.
#
# One thing the downgrade turned up that no `pip list` check could have seen.
# Reinstalling the package was not enough: `chromium-1223` was **gone from this
# machine entirely**, `executable_path` named a file that did not exist, and it
# had to be re-downloaded. So the drift was not only a Python package resolving
# forward - the browser build all 1607 control rows were measured on had been
# off the disk for some unrecorded stretch, and nothing would have said so until
# a run failed to launch. `pip list` reports which client is installed and is
# silent about which browser is on disk. The check that covers both is
# `p.chromium.launch().version`, and it is one line.
#
# These pins are the whole story only for the four packages carrying `==`. The
# unpinned six drift per host, measured the same day against the new OVH
# machine: camoufox 0.5.4 here against 0.5.6 there, cloakbrowser 0.5.7 / 0.5.10,
# zendriver 0.15.5 / 0.16.0, seleniumbase 4.51.12 / 4.54.0, curl_cffi
# 0.16.2 / 0.16.3, botasaurus-driver equal at 4.0.101. A host-against-host
# comparison is therefore sound for the control column, patchright and
# rebrowser, and confounded for the other six. Pinning them is a separate
# decision with a real cost - it freezes six anti-detect libraries whose value
# is being current - and it has not been taken.
playwright==1.60.0

# The patched Playwright driver, and the engine every Google finding here rests
# on. Pinned for the same reason as playwright above and not out of symmetry: it
# downloads its own Chromium rather than sharing Playwright's, so the version is
# the build, and `python -m patchright install chromium` is a separate download
# from Playwright's even when the two resolve to the same Chromium number.
#
# This block said until 2026-09-01 that "every patchright row in data/runs/ was
# taken on what 1.61.2 fetches". That stopped being true on 2026-08-31 and
# nothing here noticed. Measured 2026-09-01 by reading `engine_version` out of
# all 46 probehold_*.jsonl files: every run up to and including 2026-08-28 is
# `149.0.7827.55 / patchright 1.61.2`, and both ladder runs of 2026-08-31 are
# `151.0.7922.34 / patchright 1.62.2`. The workstation venv had been upgraded off
# the pin; the pin file was not the thing installing the package.
#
# Corrected an hour later, same day: the first version of this note also put the
# paired run of 2026-09-01 on 151, and only its workstation arm was. The VPS arm
# is 149.0.7827.55 / 1.61.2, because the VPS was upgraded after that run and not
# before it - engine_fingerprint_20260901T111855Z is the VPS still on 149 at
# 11:18, the ladder having finished at 11:18 too. So **the paired run is itself
# split by build**: 0/19 against 8/19 at p = 0.0031 confounds host with build and
# does not isolate either. The comparison that does hold build fixed is the
# pooled one at 149 - VPS 0/49, workstation 157/568, p = 4.5e-07 - and today's
# VPS arm belongs to it. That one holds nothing else fixed, so the two are worth
# having together and neither is worth quoting alone.
#
# The mistake from the inside: the upgrade and the run happened in the same
# session an hour apart, and "both hosts are on 1.62.2" - true when written -
# was carried backwards over a run taken before it was true. The field was in
# the rows the whole time and answering it took one read.
#
# What that cost: the three-run ladder series is split by build in the same place
# it is split by network - run 1 is 149, runs 2 and 3 are 151 - so cross-run
# yield comparisons across that boundary confound the two. The SSL/network
# finding survives, because runs 2 and 3 are both 151 and both on the same day.
#
# What the mistake looked like from the inside: the pin was treated as a
# statement about what is installed. It is only a statement about what a fresh
# `pip install -r` would install, and nothing re-reads it afterwards. The check
# that cannot go stale is the one the runs already carry - `engine_version` is
# written into every row, so the build is recoverable per run without trusting
# this file.
#
# Moved to 1.62.2 on 2026-09-01 on the user's instruction, and the VPS was moved
# with it: both hosts now report `151.0.7922.34 / patchright 1.62.2`, verified by
# engine_fingerprint.py on each. This is a re-baseline, not a bump - nothing
# taken from here on can be pooled with the 43 files on 149.
patchright==1.62.2

# A patched Chromium that hands back a Playwright browser, so it reuses the
# session class rather than adding a second request path. It is the only
# Chromium-family engine here that can align geo and humanize input, which is
# what makes those two flags measurable as axes instead of Camoufox-only
# settings.
#
# Ships its own browser binary, fetched by `cloakbrowser.ensure_binary()`.
# `cloakbrowser.download` is a module and not a function, so the call this file
# and NOTEBOOK.md both documented until 2026-08-18 raised TypeError: 'module'
# object is not callable. It went unnoticed because the workstation had the
# binary from before the instruction was written; the clone is what ran it.
cloakbrowser

# Chrome over raw CDP, no WebDriver and no Playwright. It is the second raw-CDP
# engine in the matrix and the first one whose status column works, so it is
# what makes "driven over raw CDP" readable as its own variable rather than
# something only Obscura ever measured. Uses the host's installed Chrome and
# downloads no browser.
zendriver

# The WebDriver family, which nothing else here represents. Also uses the host's
# Chrome; it fetches a matching chromedriver on first launch.
seleniumbase

# A Playwright fork sold on its Runtime.enable patch, and the second engine that
# installs a timezone override before any context exists - which is what makes
# the geo axis a 2x2 rather than one engine on each side of a guess.
#
# Pinned, and here the number is itself a finding rather than a precaution. The
# fork is behind stock Playwright by enough that `__pwInitScripts` is still an
# enumerable property of globalThis in its driver and is gone from 1.60's lib/
# entirely, so three lines of JavaScript on any page name the driver. Upstream
# removed it somewhere between 1.52 and 1.60; moving this pin moves that result
# and has to be re-measured by engine_fingerprint.py rather than assumed.
rebrowser-playwright==1.52.0

# The second post-tab timezone installer, and the control for zendriver on that
# axis: the two are 20 of 21 fingerprint markers identical, so a divergence
# between them under alignment is attributable to when the override lands rather
# than to anything a page can read. Uses the host's Chrome and downloads no
# browser, so it is unpinned for the same reason zendriver and seleniumbase are.
botasaurus-driver

# Not a browser and not trying to be one: a scriptless client wearing Chrome's
# ClientHello. It is the control that splits "no browser" from "wrong
# handshake", which `http` and the browser engines currently confound, and it is
# the cheapest engine here - no browser to download and no page to render.
curl_cffi
